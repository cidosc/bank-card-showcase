# 效果对照页（闪卡曝光检查入口）

一个**静态、零依赖**的对照页：同一张卡面并排展示 4 种效果，用于目视与量化检查「过曝 / 过暗」。

## 怎么打开

方式一（推荐，直接双击，无需服务器）：

```bash
npm run build          # 先生成 dist/（对照页引用 dist/bank-card-showcase.{css,iife.js}）
# 然后双击打开：
#   examples/effects-gallery/index.html
```

方式二（走本地服务器，`file://` 下无法读取像素做亮度统计时才需要）：

```bash
npm run build
npm run dev            # 然后访问 http://localhost:5173/examples/effects-gallery/index.html
```

## 页面内容

| 区块 | 说明 |
| --- | --- |
| 原始卡面参考（无特效） | 5 张原图（cookie / panda / panda-silver / dark / panda-card），并显示各自**实测平均亮度**、高光削波、暗部压死比例——作为“加特效前”的基线 |
| ① 项目提供的卡面（低多边形曲奇 + 麦田） | 4 种效果并排：`normal` / `holographic` / `glitter` / `silver`；浅色高光美术，最容易看出过曝 |
| ② 浅色卡面（浅绿）+ 独立银色原图 | `silver` 一列使用 `silverImage`（推荐用法：银色原图自带金属质感，特效只加光泽） |
| ③ 深色卡面（深蓝） | 深色美术最容易暴露过曝（反光冲白暗部）与过暗（反光压灰图案） |
| ④ 项目提供的卡面（低多边形熊猫 + 浅绿几何背景） | 低多边形熊猫 + 浅绿几何背景合成成的 1015×640 卡面（`public/cards/panda-card.webp`，即 Demo 商品 B 的卡面）：含明确主体与明暗层次，最容易暴露过曝/过暗 |

顶部控件（仅本页有效，不属于生产组件）：

- **质感 surface**：`flat`（默认，轻量化平面风）/ `physical`（较重的实体感）；
- **效果强度 intensity**：0–1，实时作用到页面上所有卡片，可直接看出反光层对卡面的影响幅度；
- **最大倾角 maxTilt**：0–14。

鼠标移到任意卡面上即可看到真实倾斜与反光；所有卡片共用同一套参数，便于横向对比。

## 怎么判断「过曝 / 过暗」

1. 先看上方**原始卡面参考**，记住原图的明暗与细节；
2. 再看同一卡面对应的 4 张特效卡：
   - **过曝**：高光区域糊成一片白、卡面细节（文字/图案）被冲淡 → 反光层太亮或削波；
   - **过暗**：整体发灰发闷、原图的高光被压掉 → 箔层在深色/同色系美术上把卡面压暗；
3. 把「效果强度」拉到 0 再对比一次：强度 0 时应当几乎等同原图（说明特效没有覆盖图案）。

## 自动化验收（同一套判据）

```bash
npm run acceptance     # 其中 12 项 exposure.* 检查会量化 3 张卡面 × 4 种效果的曝光
```

判据：**加特效前后卡面平均亮度偏移 ≤ 12，高光/暗部削波 ≤ 3%**（当前为 16 项：4 张卡面 × 4 种效果）。
实测数据与调整历史见 `docs/TESTING.md` 第 7 节；参数在 `src/effects.ts` 的 `BASE` 表中。

> 经验：第一轮调参只用了自制占位卡面（明暗分布平坦），结果**低估**了问题；换成有明确主体与明暗层次的
> 真实感卡面后，`holographic` 与 `glitter` 都超过了判据，才又收了一档。**换正式卡面后务必用本页再复核一次。**

> 提醒：`public/cards/` 下都是**临时占位素材**（含这张深色测试卡面）。换成你自己的正式卡面后，
> 请用本页重新目视复核一次——深色卡与浅色卡的曝光表现不同。
